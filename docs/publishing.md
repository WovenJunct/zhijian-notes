# 仓库与版本发布

## 上传源码

使用公开源码目录或 ZIP 中的文件创建仓库。上传应用源码、构建脚本、测试、文档和 `docs/images/`；README 图片使用相对路径，仓库改名或 Fork 后仍可显示。

如果开发目录的旧提交曾包含本机配置或私人记录，仅修改最新文件不会删除历史内容。使用不带 `.git` 的公开源码快照初始化新仓库，可避免推送旧开发历史。首次提交前，设置希望公开的 Git 作者名称和邮箱。

```sh
git init
git add .
git commit -m "Initial public source"
```

随后按仓库页面提供的命令连接远程地址并推送，也可使用 GitHub 的文件上传功能。以上步骤不包含自动创建远程仓库或发布。

## 本地文件

`.gitignore` 已排除签名目录、工具缓存、内部记录、构建输出、日志、环境变量文件、IDE 配置及常见私钥文件。`local.properties` 由工具准备脚本生成，无需提交。

真实笔记、备份 ZIP、发布密钥和签名密码不应进入源码仓库。签名密钥请单独保管，以便后续生成可覆盖升级的 APK。

## 发布安装包

1. 更新 `app/build.gradle` 的 `versionCode` 和 `versionName`。
2. 执行发布构建和安装包检查，记录实际验证范围。
3. 将签名 APK 与 SHA-256 校验值作为 Release 附件上传，更新版本说明。

安装包、测试报告和工具缓存不必进入源码 Git 历史。第三方许可及 `vendor-lock.json` 随源码保留。
